# T-104 solution · NullReferenceException when a unit has no current owner

**Root cause:** `StatementService.PrintStatement` does
```csharp
var currentOwner = owners.FirstOrDefault(o => o.IsCurrentOwner);
Console.WriteLine($"Owner: {currentOwner.FullName} ...");
```
Unit 112's only owner has `IsCurrentOwner = 0`, so `FirstOrDefault` returns `null`, and `.FullName` throws `NullReferenceException`.

**How you'd find it:** the stack trace says `StatementService.cs:line 20`. Put a breakpoint there, run the "T-104" profile, and the Locals window shows `currentOwner = null` and `owners` with one record (Kevin Ortiz, IsCurrentOwner = false).

The compiler had already warned about this: `warning CS8602: Dereference of a possibly null reference.` Reading build warnings is a cheap way to find bugs.

**Fix:**
```csharp
if (currentOwner is null)
    Console.WriteLine("Owner: (no current owner on file)");
else
    Console.WriteLine($"Owner: {currentOwner.FullName}  <{currentOwner.Email}>");
```
A shorter C# option is null-conditional and null-coalescing operators, which work just like TypeScript's `?.` and `??`:
```csharp
Console.WriteLine($"Owner: {currentOwner?.FullName ?? "(no current owner on file)"}");
```
