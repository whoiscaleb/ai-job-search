# T-103 solution · DATEDIFF arguments reversed

**Root cause:** `DATEDIFF(datepart, startdate, enddate)` returns `enddate - startdate`. The SELECT list is correct (`DATEDIFF(DAY, c.DueDate, @AsOfDate)`), but the WHERE clause swaps the arguments, so every past-due charge gets a negative number and nothing is "more than 30 days".

**How you'd find it:** run with `@MinDaysPastDue = -30` and rows appear. That's a big clue that a sign is flipped. Then compare the two DATEDIFF calls side by side.

**Fix:** in the WHERE clause:
```sql
AND DATEDIFF(DAY, c.DueDate, @AsOfDate) > @MinDaysPastDue
```

|---|---|---|---|
| 104 | August | 75 | $300 |
| 104 | September | 44 | $300 |
| 105 | September | 44 | $300 ← **wrong, see T-105** |
| 112 | August | 75 | $300 |
| 112 | September | 44 | $300 |

105 paid on 10/10, but the payment was applied to October instead of September, so September looks unpaid. That's T-105. Real tickets often uncover a second bug like this.
