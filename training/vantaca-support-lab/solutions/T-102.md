# T-102 solution · Balance double-counting (join fan-out) and NULL math

**Root cause (two bugs):**
1. **Fan-out.** Joining `Charges` and `Payments` to the unit at the same time produces every charge × payment combination. Unit 102 has 3 charges and 2 payments, so the join produces 6 rows. Each charge is counted 2× ($1,800) and each payment 3× ($1,800), so the balance shows $0.
2. **NULL math.** Unit 104 has no payments, so `SUM(p.Amount)` is NULL, and `900 - NULL` is NULL in SQL.

**How you'd find it:** strip the aggregates and look at the raw rows:
```sql
SELECT c.ChargeId, c.Amount, p.PaymentId, p.Amount
FROM dbo.Units u
JOIN dbo.Charges c       ON c.UnitId = u.UnitId
LEFT JOIN dbo.Payments p ON p.UnitId = u.UnitId
WHERE u.UnitId = 2;   -- 6 rows: every charge repeated per payment
```
**Rule of thumb:** never join two different "many" tables to the same parent and then SUM. Aggregate each one separately first.

**Fix:**
```sql
CREATE OR ALTER PROCEDURE dbo.usp_GetUnitBalance
    @UnitId INT
AS
BEGIN
    SET NOCOUNT ON;
    SELECT u.UnitId, u.UnitNumber,
           ISNULL(c.TotalCharged, 0) AS TotalCharged,
           ISNULL(p.TotalPaid, 0)    AS TotalPaid,
           ISNULL(c.TotalCharged, 0) - ISNULL(p.TotalPaid, 0) AS Balance
    FROM dbo.Units u
    OUTER APPLY (SELECT SUM(Amount) AS TotalCharged FROM dbo.Charges  WHERE UnitId = u.UnitId) c
    OUTER APPLY (SELECT SUM(Amount) AS TotalPaid    FROM dbo.Payments WHERE UnitId = u.UnitId) p
    WHERE u.UnitId = @UnitId;
END
```
Verified: 102 → $300.00, 104 → $900.00, 101 → $0.00.
