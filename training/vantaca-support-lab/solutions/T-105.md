# T-105 solution · Payments applied newest-first instead of oldest-first

**Root cause:** `PaymentService.RecordPayment` sorts open charges with `.OrderByDescending(c => c.DueDate)`, so a payment goes to the **newest** charge. The business rule in the class comment says oldest first.

**How you'd find it:**
```sql
SELECT pa.*, c.Description, c.DueDate
FROM dbo.PaymentApplications pa
JOIN dbo.Charges c ON c.ChargeId = pa.ChargeId
WHERE pa.PaymentId = 10;     -- applied to ChargeId 15 = October; September (14) left open
```
Then reproduce with `pay 4 300 2026-10-15 ACH`. Stepping through the loop shows charge 12 (October) paid before 10 (August).

**Code fix:**
```csharp
var openCharges = LedgerRepository.GetCharges(conn, unitId, tx)
    .Where(c => c.AmountOpen > 0)
    .OrderBy(c => c.DueDate)
    .ThenBy(c => c.ChargeId)   // stable order when two charges share a due date
    .ToList();
```
Verified: `pay 4 350` applies $300 to August (charge 10) and $50 to September (charge 11).

**Data fix:** fixing the code doesn't repair payments already applied wrong.
