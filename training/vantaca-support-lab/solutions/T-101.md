# T-101 solution · Owner directory includes former owners

**Root cause:** `usp_GetOwnerDirectory` returns every row in `Owners` for the association. Owners are kept historically (a sale ends one owner's record and starts another), and the procedure never filters on `IsCurrentOwner`.

**How you'd find it:** `SELECT * FROM dbo.Owners WHERE UnitId = 3;` shows two rows for 103: Dana (IsCurrentOwner = 0, EndDate 2026-07-15) and Marcus (IsCurrentOwner = 1).

**Fix:** add the filter.
```sql
CREATE OR ALTER PROCEDURE dbo.usp_GetOwnerDirectory
    @AssociationId INT
AS
BEGIN
    SET NOCOUNT ON;
    SELECT u.UnitNumber, o.FirstName, o.LastName, o.Email, o.Phone
    FROM dbo.Owners o
    JOIN dbo.Units u ON u.UnitId = o.UnitId
    WHERE u.AssociationId = @AssociationId
      AND o.IsCurrentOwner = 1
    ORDER BY u.UnitNumber, o.LastName;
END
```
Result: 5 rows (101, 102, 103 Marcus Lee, 104, 105).

**The unit 112 question:** 112 has no current owner (it was foreclosed), so it vanishes. A board mailing list arguably should still show the unit. A version that keeps every unit:
```sql
SELECT u.UnitNumber,
       ISNULL(o.FirstName, '(no current owner)') AS FirstName,
       o.LastName, o.Email, o.Phone
FROM dbo.Units u
LEFT JOIN dbo.Owners o ON o.UnitId = u.UnitId AND o.IsCurrentOwner = 1
WHERE u.AssociationId = @AssociationId
ORDER BY u.UnitNumber;
```
Putting `IsCurrentOwner = 1` in the **ON** clause of a LEFT JOIN keeps unmatched units. In the WHERE clause, it would drop them again. This is one of the most useful SQL details to really understand.
